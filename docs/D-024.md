# D-024 publisher leg

Plugin 0.1.14. Draft pull request into `staging` only.

## Disclosure

The plugin and `POST /v1/placements/:id/receipt` share one rule. After tags are stripped and the text is lowercased, a disclosure is the approved sentence, the word `commissione`, or `link` within 60 characters of `affiliat` in either order. "Leggi la nostra disclosure policy", "contenuto sponsorizzato", and "contiene link" do not match. The shared phrases live in `affilio-wp/tests/fixtures/disclosure-match.json` and are asserted from Go and PHP.

A refused receipt restores the post. That automatic revert does not call `POST /v1/placements/:id/removed`, because the placement was never accepted. The excerpt sent with a receipt is cut with `mb_substr` on character boundaries.

## Block marker

An insert is a core paragraph:

```
<!-- wp:paragraph {"className":"affilio-placement-<id>"} -->
<p class="affilio-placement-<id>">…</p>
<!-- /wp:paragraph -->
```

A disclosure the plugin adds uses `affilio-disclosure-<id>` the same way. `@wordpress/blocks` `parse()` accepts that markup as a valid `core/paragraph` on the current save, with no deprecation. Revert finds the class token, including when the editor adds another class.

The 0.1.13 comment `<!-- distributoor-placement:<id> -->` is still removed, both in front of the `<p>` and after an editor re-save. That re-save fixture is `affilio-wp/tests/fixtures/editor-resave-013.txt`. `editor-resave-013.note.txt` records that it came from `serialize(parse(...))` with `@wordpress/blocks` and `@wordpress/block-library`.

## Manual revert

`Rimuovi inserimento` asks for confirmation of the post title and the exact link (anchor text and go URL), with Annulla and Rimuovi. The post is edited first. The API report is best-effort. A failed report is queued in `affilio_removal_queue` and retried on the `affilio_retry_removals` cron hook, with backoff, and then dropped. The notice says `API: segnalato`, `API: già rimosso`, or `API: non raggiungibile, riprovo più tardi`.

`wp affilio revert <post_id> [--placement=<id>] [--dry-run]` uses the same function. It prints the post change and the API result separately. Exit 0 when the local revert succeeded. Exit non-zero only when nothing matched locally. `--dry-run` does not call the API.

## Removal API

`POST /v1/placements/:id/removed` uses the site API key, the same way as the receipt. Another site's placement is 404. Marking an already-removed placement returns 200 with `already_removed: true`.

Migration `016_placement_removed_at.sql` adds nullable `removed_at timestamptz`. It does not drop or rename anything. Applying it on a table that already has placements leaves those rows in place with `removed_at` null.

`GET /v1/go/<code>?placement=<id>` for a removed placement still responds 302 to the offer destination. It records no click and no attribution, and the `via` parameter is omitted.

The owner placement review and the no-JavaScript owner inbox show `Rimosso` with the date. The maker dashboard, including the no-JavaScript publisher-placements section, shows the same label. The workspace script uses `removed_at` for the same text.
